# drawDB キャンバス操作 vs Figma 対照表

drawDB エディタのキャンバス操作と Figma との違い、および本ブランチ（`feat/space-pan`）で Figma に合わせた変更点をまとめたドキュメントです。

- Windows / Linux では `Ctrl`、macOS では `Cmd` に対応します（コード上は `mod` でバインド）。
- ステータス：✅ Figma と同じ　🆕 本ブランチで追加　⚠️ 動作が異なる（意図的に維持）　❌ 未対応
- 入力欄、テキストエリア、ノートの編集領域、DBML/SQL コードエディタにフォーカスがある場合、以下のショートカットは**一切発動せず**、通常の文字入力として動作します。

---

| マウスホイール                                | 縦スクロール                           | 縦スクロール           | 縦スクロール                                                                   | ✅                                 |
| `Shift` + ホイール                            | 横スクロール                           | 横スクロール           | 横スクロール                                                                   | ✅                                 |

## 実装メモ

変更したファイル：

- `src/components/EditorCanvas/Canvas.jsx`
  - スペース + ドラッグでのパン（キャプチャフェーズでポインターイベントを捕捉するため、要素はドラッグされない）
  - `Shift` + クリック / 範囲選択での追加選択
  - ホイール処理：`deltaX` に対応。トラックパッドのピンチは量に応じてズーム。Firefox の行 / ページ単位をピクセルに換算
- `src/components/EditorHeader/ControlPanel.jsx`
  - 追加ショートカット：`Shift+0/1/2`、`Ctrl+=/-`、`Ctrl+A`、`Esc`、`Backspace`、`Ctrl+Shift+Z`、`Shift+矢印キー`
  - 複数選択の削除に対応。ノートとエリアは削除後に id が振り直されるため、id の大きい順に削除して誤削除を防止
  - 矢印キー：要素選択時は要素を移動（元に戻す履歴に記録）、未選択時はキャンバスをパン
  - `fitToView` を指定した要素だけで範囲計算できるように変更（`Shift+2` で使用）。要素がない場合に NaN になる問題も修正
  - リレーションでつながった 2 つのテーブルを同時に削除して元に戻した際、リレーションが重複して追加されないように修正
  - メニューに表示されるショートカット表記も更新

## 既知の制限

- ショートカットは**物理キー**（`KeyboardEvent.code`）で判定します。`Ctrl+=` は JIS キーボードでは `^` キーに当たるため、JIS の `+` がある `Ctrl+;` も追加でバインドしています。
- ボタンにフォーカスがある場合、スペースはパンに使われるため、ボタンのクリックとしては動作しません。
- 矢印キーは 1 回押すごとに元に戻す履歴が 1 件記録されます（Figma のように連続移動を 1 件にまとめる処理はしていません）。
- 切り取り（`Ctrl+X`）はコピーと同様、引き続き単一要素のみが対象です。
