# 右键菜单 & 区域整体移动：设计思路

本文档说明 `feat/space-pan` 分支中两个功能的设计思路、实现方式和取舍：

1. **右键菜单**：在画布上右键单击时，显示 drawDB 自己的菜单，而不是浏览器菜单。
2. **区域整体移动**：拖动主题区域（Subject Area）时，完全位于区域内的表格、视图、注释和子区域一起移动，类似 Figma 的 Section。

---

## 1. 背景

### 1.1 改动前的情况

| 项目               | 改动前                                                   |
| ------------------ | -------------------------------------------------------- |
| 右键拖动           | 平移画布                                                 |
| 右键单击（不拖动） | 弹出浏览器自带菜单（返回、刷新、检查等），对编辑没有帮助 |
| 主题区域           | 只是一个背景框；拖动区域时，里面的表格不会跟着动         |
| 分组               | 没有                                                     |

上游也有相关反馈：

- [drawdb-io/drawdb#1107](https://github.com/drawdb-io/drawdb/issues/1107)：Chrome 上右键会先弹出浏览器菜单，平移有时不生效。
- [drawdb-io/drawdb#56](https://github.com/drawdb-io/drawdb/issues/56)、[drawdb-io/drawdb#1003](https://github.com/drawdb-io/drawdb/issues/1003)：希望有表格分组，或者把区域当作父容器。

### 1.2 方案选择

分组有两种做法：

| 方案                            | 内容                                             | 工作量 | 数据格式                         |
| ------------------------------- | ------------------------------------------------ | ------ | -------------------------------- |
| **A：区域整体移动**（本次采用） | 拖动区域时，按位置判断哪些元素在区域里，一起移动 | 小     | 不变，和上游兼容                 |
| B：真正的分组                   | 给元素加分组 id，`Ctrl+G` 分组，点一个选中整组   | 大     | 需要改，保存、导入、导出都受影响 |

方案 A 不需要新增数据，"哪些元素属于这个区域"每次拖动时按位置现算，所以和上游 drawDB 保存的文件完全兼容。大部分"整体移动"的需求用方案 A 就能满足，方案 B 以后有需要再做。

## 2. 右键菜单

### 2.1 交互设计

- **右键拖动**：和以前一样平移画布，松开后**不弹出**任何菜单。
- **右键单击**：弹出 drawDB 菜单。
- **右键点在文本框、输入框里**：保留浏览器菜单，方便复制、粘贴文字。
- **选中规则（和 Figma 一致）**：
  - 右键点在**未选中**的元素上：先选中这个元素，再显示它的菜单。
  - 右键点在**已选中**的元素上：保持当前选择。如果当前是多选，显示多选菜单。
- **关闭菜单**：点击菜单以外的地方、按 `Esc`、滚动滚轮、执行任意菜单项。
- **位置**：菜单出现在光标右下方；右边或下边空间不够时，自动翻到另一侧。

### 2.2 菜单内容

| 右键位置                           | 菜单项                                                         |
| ---------------------------------- | -------------------------------------------------------------- |
| 空白处                             | 粘贴、全选 ／ 显示全部、缩放到 100%、重置视图                  |
| 单个元素（表格、视图、注释、区域） | 编辑 ／ 复制、剪切、原地复制 ／ 锁定或解锁、缩放到选中 ／ 删除 |
| 多选                               | 缩放到选中 ／ 删除（N）                                        |

- 每一项右侧都显示对应的快捷键，和顶部菜单的写法一致。
- 只读模式下，会修改图表的菜单项（编辑、剪切、粘贴、删除等）显示为禁用。

### 2.3 实现思路

#### 问题：菜单要调用的操作写在顶部工具栏里

编辑、复制、粘贴、删除这些操作都写在 `ControlPanel.jsx`（顶部工具栏）里，画布组件 `Canvas.jsx` 调用不到。

可以考虑的做法：

| 做法                                                         | 优点                                   | 缺点                                             |
| ------------------------------------------------------------ | -------------------------------------- | ------------------------------------------------ |
| 把所有操作抽到一个新的 hook / context                        | 结构最干净                             | 要搬动上千行代码，改动大，以后和上游合并容易冲突 |
| **由 `ControlPanel` 把操作登记到一个共享的 ref**（本次采用） | 改动小，菜单和快捷键运行的是同一份代码 | 多了一层间接调用                                 |

具体做法：

1. `Workspace.jsx` 创建 `editorActionsRef`，同时传给 `ControlPanel` 和 `Canvas`。
2. `ControlPanel` 每次渲染后，把最新的操作函数写进 `editorActionsRef.current`：
   `edit`、`copy`、`cut`、`paste`、`duplicate`、`deleteSelection`、`toggleLock`、`selectAll`、`zoomToSelection`、`fitWindow`、`resetZoom`、`resetView`，以及 `readOnly` 标志。
3. 菜单点击时调用 `editorActionsRef.current.xxx()`。因为每次渲染都会更新，函数里读到的选中状态总是最新的。

#### 区分"右键单击"和"右键拖动"

原代码已经有 `rightClickPanned` 这个 ref：右键松开时，如果画布被平移过，它就会被设为 `true`。在 `contextmenu` 事件里：

```
rightClickPanned 为 true  → 阻止浏览器菜单，不显示 drawDB 菜单（这次是拖动）
点在 input / textarea 里  → 什么都不做，保留浏览器菜单
其他情况                   → 阻止浏览器菜单，显示 drawDB 菜单
```

#### 判断右键点中了哪个元素

画布原来就有一个约定：表格、注释、区域等元素在 `pointerdown` 时，把自己写进 `elementPointerDown`，然后事件冒泡到 svg 的 `handlePointerDown` 再统一处理。

右键按下时，把 `elementPointerDown` 存到 `contextMenuTarget` 这个 ref 里；`contextmenu` 事件触发时读出来使用，用完立即清空。

#### 菜单组件

新增 `src/components/EditorCanvas/ContextMenu.jsx`：

- 使用项目已有的 Semi UI `Dropdown`，`trigger="custom"` 并固定 `visible`，外观和深色模式与顶部菜单一致。
- 在光标位置放一个 1×1 的 `position: fixed` 透明元素作为锚点，让 Dropdown 以它为基准定位，所以超出屏幕时会自动翻转。
- 用光标坐标作为 `key`：每次右键都重新挂载，保证位置正确。

#### 新增的翻译

新增 4 个 key：`select_all`、`zoom_to_fit`、`zoom_to_selection`、`zoom_to_100`，写入了 `en`、`zh`、`zh-tw`、`jp`。其他语言没有这些 key 时，会自动显示英文（`fallbackLng: "en"`）。

## 3. 区域整体移动

### 3.1 交互设计

- **拖动区域**：完全位于区域内的表格、视图、注释、子区域一起移动。
- **按住 `Alt` 拖动区域**：只移动区域本身，用于调整区域位置。
- **方向键移动选中的区域**：内容同样跟着移动。键盘上不提供 `Alt` 版本，因为 `Alt+←` 是浏览器的"返回"。
- **撤销**：区域和内容的移动记为**一条**撤销记录，按一次 `Ctrl+Z` 全部还原。
- **判断"在区域里"**：元素的矩形必须**完全**在区域矩形内。只压住一部分的元素不会跟着动。
- **不跟着动的元素**：
  - 已锁定的元素。
  - 本身已经被选中的元素：它们已经随选择一起移动，不会重复移动。

### 3.2 实现思路

#### 公共函数：`src/utils/elementBounds.js`

- `getElementBounds(diagram)`：返回所有表格、视图、区域、注释在图表坐标里的矩形。表格和视图的宽高用项目已有的 `getTableWidth`、`getTableHeight`、`getViewWidth`、`getViewHeight` 计算。
- `getAreaContents(areaIds, diagram, exclude)`：找出完全位于这些区域内的元素，跳过已锁定的元素和 `exclude` 里的元素。判断用项目已有的 `isInsideRect`。

拖动（`Canvas.jsx`）和键盘移动（`ControlPanel.jsx`）都调用这同一个函数，所以两边的判断规则一致。

#### 拖动（`Canvas.jsx`）

1. `dragging` 状态新增 `areaContents` 字段（默认空数组）。
2. 按下开始拖动时（`handlePointerDownOnElement`）：
   - 如果被拖动的元素里有区域，并且没有按 `Alt`，就用 `getAreaContents` 算出区域里的元素，存进 `dragging.areaContents`。
   - 区域里的元素**不加入选择**。如果加入选择，拖完之后它们会保持选中，用户再按 `Delete` 就会连表格一起删掉，这很危险。
3. 移动时（`handlePointerMove`）：用同一个位移量，同时移动选中的元素和 `areaContents`。
4. 松开时（`handlePointerUp`）：撤销记录同时包含选中的元素和 `areaContents`，所以一次撤销就能全部还原。

#### 键盘移动（`ControlPanel.jsx` 的 `nudgeOrPan`）

先计算选中的区域里有哪些元素，再把它们和选中的元素一起移动，最后写入一条撤销记录。

## 5. 测试结果

在本地 dev server 上验证通过：

| 测试项              | 结果                                                     |
| ------------------- | -------------------------------------------------------- |
| 右键单击空白处      | 显示空白处菜单，浏览器菜单被阻止                         |
| 右键单击元素        | 先选中元素，再显示该元素的菜单                           |
| 右键拖动            | 画布平移，不弹出任何菜单                                 |
| `Esc` / 点击菜单外  | 菜单关闭                                                 |
| 菜单「原地复制」    | 生成一个副本                                             |
| 菜单「锁定 / 解锁」 | 状态切换；再次右键时，菜单文字随之改变                   |
| 多选后右键          | 显示多选菜单；「删除」会删除所有选中元素，撤销后全部恢复 |
| 拖动区域            | 区域内的注释一起移动，部分重叠的表格不动                 |
| `Alt` + 拖动区域    | 只有区域移动                                             |
| 撤销区域拖动        | 一次 `Ctrl+Z` 全部还原                                   |
| 方向键移动区域      | 内容一起移动；一次撤销全部还原                           |

## 6. 已知限制和后续可以做的

- **Mac 上的 `Ctrl+点击`**：这个操作也会触发右键菜单，但那时左键的处理逻辑先运行，菜单可能不会对准被点的元素，会显示成空白处菜单。目前没有专门处理。
- **"属于区域"按位置现算**：元素被拖出区域，就自动不再属于这个区域。好处是不用存数据；缺点是没法让一个只压住区域边缘的元素也跟着动。
- **区域重叠或嵌套**：拖动外层区域时，内层区域和它里面的元素也会一起移动（因为它们都在外层区域内）。
- **后续可以做**：
  - 方案 B：真正的分组，带 `groupId`，并支持分组和取消分组。
  - 菜单增加更多操作：对齐、调整层级、修改颜色、在光标位置粘贴等。
  - 把 `ControlPanel` 里的操作逐步抽成独立的 hook，最后去掉共享 ref 这一层。
